# W3 — cara profesor

**Objetivo:** el profesor ingresa una pregunta propia y ve, por cada distractor, los errores más probables del catálogo. El recuperador corre en el navegador, en un Web Worker. El servidor es opcional.

**Especificación:** `docs/diseno.md`, secciones 5.2, 5.3, 5.5 y 5.6. **Base:** lo que dejó W1.

**Carpetas que tocas:** `web/src/app/diagnose/**`, `web/src/app/core/{format,ranker,embedder.service,embedder.worker,api.service}.ts`, sus pruebas, y en `app.routes.ts` solo la ruta `diagnosticar`. Informe en `docs/informes/w3.md`.

## Lógica pura

```ts
// core/format.ts — must match ml/ exactly (docs/diseno.md 5.3)
export function formatQuery(stem: string, correct: string, wrong: string): string
//   => `query: Wrong answer: ${wrong}\nCorrect answer: ${correct}\nQuestion: ${stem}`
export function formatPassage(name: string): string   // => `passage: ${name}`

// core/ranker.ts
export interface Ranked { index: number; score: number }
export function rankCatalog(query: Float32Array, catalog: Float32Array, dim: number, k: number): Ranked[]
//   dot product of the query against each row of `catalog` (rows and query are L2-normalised), best first
export function diagnose(ranked: Ranked[], threshold: number, top?: number): Ranked[]
//   top = 3; returns [] when the best score is below threshold ("sin diagnóstico claro")
```

## Modelo en el navegador

- `EmbedderService` (`core/embedder.service.ts`) expone `status` (`'idle' | 'loading' | 'ready' | 'error'`), `progress` (0 a 1) y `embed(texts: string[]): Promise<Float32Array[]>` (vectores normalizados). Delega en `embedder.worker.ts`, que carga el modelo con `@huggingface/transformers` (*feature extraction*, *mean pooling*, normalización, pesos cuantizados). Confirma la API vigente en su documentación.
- Origen del modelo, por token de inyección `MODEL_SOURCE`: `{ kind: 'hub', id: string }` o `{ kind: 'local', path: string }`. Por defecto `{ kind: 'hub', id: 'Xenova/multilingual-e5-small' }` mientras no existan artefactos reales.
- El modelo se carga solo al entrar a `/diagnosticar` y con una acción explícita del usuario ("Cargar modelo, 118 MB"), mostrando el avance.
- Embeddings del catálogo: si `manifest.model_id === 'fixture-random-vectors'`, `catalog.f32` no sirve; se calculan en el navegador con `embed(formatPassage(name))` y se guardan en memoria. En cualquier otro caso se usa `catalog.f32`.

## Servidor opcional — `core/api.service.ts`

Token `API_BASE_URL` (cadena vacía = sin servidor). `structure(text): Promise<StructuredQuestion>` y `reinforce(input): Promise<string>` contra `POST /api/structure` y `POST /api/reinforce`. Cualquier fallo (red, 429, 502, 503) se convierte en `ApiUnavailableError`; la página nunca queda bloqueada por él.

## Pantalla `/diagnosticar`

1. Área para pegar texto y botón "Ordenar con IA": solo visible si hay servidor. Si falla, aviso breve y el formulario queda para llenarlo a mano.
2. Formulario: enunciado, alternativas A a D, cuál es la correcta. Vista previa compuesta en vivo con `app-math-text`, junto a cada campo. Ayuda breve: "Escribe matemática entre `$...$`, por ejemplo `$\frac{1}{2}$`".
3. Validación antes de diagnosticar: enunciado y cuatro alternativas no vacíos, alternativas distintas entre sí, una correcta marcada.
4. Opcional: número de estudiantes que marcó cada distractor. Solo ordena la pantalla (más marcado primero); no entra al modelo.
5. Resultado por distractor: hasta 3 errores con nombre, descripción y puntaje, o "sin diagnóstico claro" si el mejor puntaje queda bajo `manifest.threshold`. Cada error muestra su `activity`. Aviso visible de que es una hipótesis.
6. "Pedir ejercicio de refuerzo" por error: usa el servidor; si no hay o falla, se queda con la `activity`.
7. "Descargar pregunta": archivo JSON con una pregunta en el formato de `bank.json` (`id` generado, `topic` elegido por el profesor, `tags` solo para los distractores, con `source: 'model'` y los puntajes).

## Pruebas obligatorias

- `formatQuery('S','c','w')` es exactamente `"query: Wrong answer: w\nCorrect answer: c\nQuestion: S"`; `formatPassage('n')` es `"passage: n"`.
- `rankCatalog` con catálogo de 3 vectores unitarios de dimensión 3 y consulta `[0,1,0]` → primer índice 1 con puntaje 1; con `k=2` devuelve 2 elementos en orden descendente.
- `diagnose` devuelve `[]` si el mejor puntaje es menor que el umbral, y a lo más `top` elementos si no.
- `ApiService`: con `API_BASE_URL` vacío rechaza sin hacer petición; ante 429, 502, 503 y error de red rechaza con `ApiUnavailableError`.
- Página con `EmbedderService` falso (vectores fijos): llenar el formulario y diagnosticar muestra un bloque por cada uno de los 3 distractores y ninguno para la correcta.
- Con conteos `C: 20, A: 5, D: 0`, los bloques salen en orden C, A, D.
- Alternativas repetidas o sin correcta marcada: no se diagnostica y se muestra el motivo.
- La pregunta descargada tiene `tags` para exactamente los tres distractores y pasa las mismas reglas que `contracts/bank.schema.json` (comprueba forma y tipos en la prueba).
- Fallo de `reinforce`: se muestra la `activity` del catálogo.

El Worker con el modelo real no se prueba en la suite. Verifícalo a mano una vez con `npm start` y anota en el informe: tiempo de descarga, tiempo por diagnóstico y los errores que devolvió para la pregunta `F-01` del fixture.

## Criterio de aceptación

`npm run lint`, `npm test` y `npm run build` pasan en `web/`. Con el modelo base, la página ordena los 6 errores del fixture para una pregunta escrita a mano, sin servidor.
