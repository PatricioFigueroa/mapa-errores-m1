# S1 — servidor Express

**Objetivo:** un servicio sin estado en `server/` con las dos funciones que usan LLM. La web funciona sin él; este servicio solo mejora la experiencia.

**Especificación:** `docs/diseno.md`, secciones 5.5 y 5.6.

**Carpetas que tocas:** `server/` y `.github/workflows/server.yml`. Nada más.

## Restricciones

- Node 24, TypeScript estricto, Express 5, `zod` para validar, `vitest` y `supertest` para pruebas. Sin SDK de proveedores: se llama con `fetch` a una API compatible con OpenAI (`POST {base}/chat/completions`).
- Los tests no usan red: el proveedor se inyecta y en pruebas es falso.
- Nunca registres el cuerpo de las peticiones ni la clave. Nada se guarda en disco.
- Código, comentarios y commits en inglés (Conventional Commits). Los *prompts* van en español.

## Interfaces

```ts
// server/src/llm.ts
export interface LlmRequest { system: string; user: string; maxTokens: number; json?: boolean }
export interface LlmProvider { complete(req: LlmRequest): Promise<string> }
export class LlmQuotaError extends Error {}        // provider answered 429
export class LlmUnavailableError extends Error {}  // network failure, timeout or 5xx
export function openAiCompatible(opts: { baseUrl: string; apiKey?: string; model: string; timeoutMs?: number }): LlmProvider
export function withFallback(primary: LlmProvider, fallback?: LlmProvider): LlmProvider  // tries fallback on quota/unavailable

// server/src/app.ts
export interface AppDeps { llm: LlmProvider; allowedOrigins: string[]; dailyCap: number; perMinute: number; now?: () => Date }
export function createApp(deps: AppDeps): express.Express

// server/src/config.ts
export function loadConfig(env: NodeJS.ProcessEnv): AppDeps
```

Variables de entorno (documentadas en `server/.env.example`): `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, opcionales `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_MODEL`; `ALLOWED_ORIGINS` (separados por coma; por defecto `http://localhost:8100,http://localhost:4200`); `DAILY_CAP` (200); `PER_MINUTE` (10); `PORT` (3000).

Ejemplos que debe traer `.env.example`: Groq (`https://api.groq.com/openai/v1`, modelo `openai/gpt-oss-20b`) y Ollama local (`http://localhost:11434/v1`, modelo `qwen3.5:4b-q4_K_M`, sin clave).

## Rutas

| Ruta | Entrada (JSON) | Salida 200 |
|---|---|---|
| `GET /api/health` | — | `{ "ok": true }` |
| `POST /api/structure` | `{ "text": string }`, 1 a 4.000 caracteres | `{ "stem": string, "options": { "A": string, "B": string, "C": string, "D": string }, "answer": "A" \| "B" \| "C" \| "D" \| null }` |
| `POST /api/reinforce` | `{ "stem": string, "correct": string, "wrong": string, "error": { "id": string, "name": string } }`, cada texto hasta 2.000 caracteres | `{ "exercise": string }`, hasta 1.500 caracteres |

Errores, siempre `{ "error": código }`:

| Situación | Estado | Código |
|---|---|---|
| Cuerpo inválido o fuera de límites | 400 | `bad_request` |
| Supera `PER_MINUTE` por IP o `DAILY_CAP` global | 429 | `quota` |
| El proveedor (y su respaldo) respondió 429 | 429 | `quota` |
| El proveedor (y su respaldo) no responde | 503 | `unavailable` |
| La salida del LLM no cumple el esquema tras un reintento | 502 | `bad_output` |

Reglas:

- Cuerpo máximo 16 kB. CORS solo para `allowedOrigins`.
- `DAILY_CAP` cuenta peticiones a `/api/structure` y `/api/reinforce` en memoria y se reinicia a medianoche UTC (usa `now` para probarlo).
- `/api/structure`: el *prompt* pide solo JSON con el esquema de salida, matemática en LaTeX entre `$...$`, sin resolver el ejercicio; `answer` es `null` salvo que el texto marque la correcta. La respuesta del LLM se extrae (puede venir rodeada de texto o en un bloque de código), se valida con `zod` y, si falla, se reintenta **una** vez.
- `/api/reinforce`: el *prompt* pide un único ejercicio breve, en español, dirigido al error recibido, sin incluir la solución. La salida se recorta a 1.500 caracteres.

## Pruebas obligatorias

- `GET /api/health` responde 200.
- `/api/structure` con proveedor falso que devuelve JSON válido rodeado de texto y de un bloque ```` ```json ```` responde 200 con las cuatro alternativas.
- `/api/structure` cuando el proveedor devuelve `options` como **lista** la primera vez y el objeto correcto la segunda: responde 200 y el proveedor fue llamado dos veces.
- `/api/structure` cuando el proveedor devuelve basura dos veces: 502 `bad_output`.
- `/api/structure` con `text` vacío o de 4.001 caracteres: 400, y el proveedor no fue llamado.
- `/api/reinforce` recorta una salida de 5.000 caracteres a 1.500.
- Proveedor que lanza `LlmQuotaError`: 429 `quota`. Proveedor que lanza `LlmUnavailableError`: 503 `unavailable`.
- `withFallback`: si el primario lanza `LlmQuotaError`, se usa el respaldo y responde 200.
- Con `dailyCap: 2`, la tercera petición del día responde 429; tras avanzar `now` al día siguiente, vuelve a responder 200.
- Origen no permitido: la respuesta no trae `Access-Control-Allow-Origin`.
- `openAiCompatible` con `fetch` simulado: envía `Authorization` solo si hay clave; traduce 429 a `LlmQuotaError` y 500 a `LlmUnavailableError`.

## Notas

- Con Ollama y modelos que "piensan" (Qwen 3.5), la respuesta puede traer `content` vacío si `max_tokens` es bajo, porque el razonamiento consume el presupuesto. Usa `maxTokens` de al menos 800 y deja en `server/scripts/smoke.ts` una prueba manual contra un proveedor real (no corre en CI).
- `server/src/index.ts` solo arranca `createApp(loadConfig(process.env))` en `PORT`.
- CI en `.github/workflows/server.yml`: en cambios bajo `server/`, ejecutar `npm ci`, `npm run lint`, `npm test`, `npm run build`.

## Criterio de aceptación

`npm run lint`, `npm test` y `npm run build` pasan dentro de `server/`, sin red.
