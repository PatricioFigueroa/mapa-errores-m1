# Núcleo ML (paquete P1) — plan de implementación

> **Para quien ejecute:** avanza tarea por tarea, en orden. Cada paso es una acción con resultado comprobable; marca las casillas (`- [ ]`) al cumplirlas. Lee antes `AGENTS.md` y la especificación.

**Objetivo:** tener en el equipo del autor métricas, carga de datos Eedi, cuatro líneas base, un primer afinado y una CLI que diagnostica una pregunta.

**Arquitectura:** un paquete Python `mapa_errores` en `ml/`. Todo recuperador cumple la misma interfaz (`fit`, `rank`), de modo que evaluación y CLI no saben cuál usan. Los datos de Eedi viven fuera de git en `data/eedi/`.

**Tecnología:** Python 3.12, `uv`, `numpy`, `pandas`, `scikit-learn`, `rank-bm25`, `sentence-transformers`, `torch` con CUDA, `kaggle`, `pytest`, `ruff`.

**Especificación:** [../diseno.md](../diseno.md), secciones 4, 5.3 y 6.

## Restricciones globales

- Python 3.12 fijado en `ml/.python-version`. Solo `uv`; nunca `pip`.
- `.gitignore` incluye `data/eedi/`, `artifacts/`, `ml/runs/`, `.venv/`. Ningún texto de Eedi entra a git, tampoco en fixtures: las filas de prueba son inventadas.
- Formato de texto, exacto: `query: Wrong answer: {wrong}\nCorrect answer: {correct}\nQuestion: {stem}` y `passage: {name}`.
- Modelo base: `intfloat/multilingual-e5-small`. Valores por defecto: `max_seq_length=192`, `batch_size=32`, `mini_batch_size=16`, `epochs=3`, `lr=2e-5`, `fp16=True`.
- Toda función con azar recibe `seed: int`.
- Los tests corren sin GPU, sin red y sin datos de Eedi. Los que descargan un modelo llevan `@pytest.mark.slow` y no corren en CI.
- Código, comentarios y commits en inglés, con Conventional Commits.
- Windows 11, GTX 1650 de 4 GB.

## Foco de revisión

Casos que la especificación implica y que más pueden morder. Cada uno tiene su prueba en la tarea indicada.

1. Distractor sin error etiquetado (celda vacía): no genera fila y se cuenta en el informe. Tarea 2.
2. Enunciado muy largo: el distractor no puede perderse al truncar. Tarea 3.
3. Mismo enunciado con dos identificadores distintos: debe caer en la misma partición. Tarea 3.
4. Error de la prueba que no aparece en entrenamiento: se evalúa igual y se reporta aparte. Tarea 4.
5. Dos errores del catálogo con el mismo texto: la evaluación compara posiciones del catálogo, no textos. Tarea 4.

- Produce:
  - `build_training_dataset(train: pd.DataFrame, catalog: pd.DataFrame, model, hard_negatives: int = 2) -> datasets.Dataset` con columnas `anchor`, `positive`, `negative_1` … `negative_n`.
  - `finetune(train: pd.DataFrame, catalog: pd.DataFrame, out_dir: Path, base_model: str = "intfloat/multilingual-e5-small", epochs: int = 3, batch_size: int = 32, mini_batch_size: int = 16, max_seq_length: int = 192, lr: float = 2e-5, hard_negatives: int = 2, seed: int = 0, fp16: bool = True) -> Path` — devuelve la carpeta del modelo guardado.

Decisiones fijadas (API confirmada en sbert.net el 2026-11-09):
- `SentenceTransformerTrainer` con `losses.CachedMultipleNegativesRankingLoss(model, mini_batch_size=...)`.
- `SentenceTransformerTrainingArguments(batch_sampler=BatchSamplers.NO_DUPLICATES, fp16=...)`, para que un mismo error no actúe como negativo de sí mismo.
- Negativos difíciles con `sentence_transformers.util.mine_hard_negatives`, usando el catálogo completo como corpus. `build_training_dataset` comprueba con un `assert` que ningún negativo es igual a su positivo.
